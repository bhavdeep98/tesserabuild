Anatomy of a YAML Connector Definition

Each connector is a single YAML file that the Generic Connector Runtime interprets at startup. No compilation, no custom classes.

version: "2.0" source_system_id: "SALESFORCE" lifecycle_stage: "sales" auth: type: "jwt_bearer" token_url: "${SF_LOGIN_URL}/services/oauth2/token" credentials: client_id: "${SF_CLIENT_ID}" private_key_path: "${SF_PRIVATE_KEY_PATH}" endpoints: - id: "opportunities" url: "${SF_INSTANCE_URL}/services/data/v59.0/query" pagination: { strategy: "cursor", page_size: 200 } transition_rules: - tracked_field: "stage" from: ["Prospecting", "Negotiation"] to: ["Closed Won", "Under Contract"] emit_signal: "contract_signed"
Technical Deep Dive

State Tracking & Transition Rules

The runtime remembers what it saw last time. Signals only fire when tracked fields actually change — preventing duplicates.

State Tracking

Each record's key fields are persisted between poll cycles. On the next poll, the runtime compares current vs. stored values. Only changed records proceed to rule evaluation.

Transition Rules

Declarative "from → to" rules. When a tracked field transitions from one value to another, emit a specific signal. Supports wildcards (*), null (first-seen), and arrays (match any).

# Example: Emit "foundation_complete" when status goes from # null or in_progress → completed state_tracking: fields: - { path: "phases.Foundation.status", key: "foundation_status" } transition_rules: - tracked_field: "foundation_status" from: [null, "not_started", "in_progress"] to: "completed" emit_signal: "foundation_complete"

Hooks: When YAML Isn't Enough

Some APIs return data in unusual shapes. Hooks are optional TypeScript functions that transform data before or after polling.

Post-Poll Hook (Procore example)

Procore returns a flat list of schedule tasks. The hook groups them by construction phase (Foundation, Framing, etc.) and derives per-phase completion status. The runtime can then track "phases.Foundation.status" as if it were a native API field.

State Comparator Hook (Salesforce)

Custom comparison logic for determining if a record has meaningfully changed. Useful when the source system's "LastModifiedDate" fires on irrelevant field changes.

# In the YAML definition: hooks: post_poll: path: "./hooks/schedule-normalizer.ts" export_name: "normalizeScheduleData"

Most connectors need zero hooks. Only 2 of 6 current connectors use them (Procore and Salesforce). The YAML handles the common case; hooks handle the edge cases.

Technical Deep Dive

Generic Connector Runtime

One runtime engine that interprets ALL connector definitions. No per-connector deployment.

Components

AuthStrategyFactory (handles all auth types) → PaginatedPoller (handles cursor/offset/page) → StateTracker (change detection) → TransitionRuleEvaluator (signal emission) → HookLoader (optional transforms)

Safety Mechanisms

Circuit breaker (opens after consecutive failures), rate limit backoff (respects 429 + Retry-After headers), EgressGuard (only GET/HEAD allowed — physically cannot write), idempotent signal emission

Auth Types

OAuth2 Client Creds, OAuth2 Password, JWT Bearer, API Key, Basic

Pagination

Offset, Cursor, Page-based — auto-detected from YAML config

Dedup Modes

on_change (re-emit on field change) or once_only (emit at most once per record)

Authentication Strategies

The runtime handles 5 auth types. Credentials are always env-var references — never stored in YAML files.
